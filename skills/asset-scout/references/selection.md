# 选材与来源记录

## 按镜头判断可用性

先明确镜头要证明事实、解释关系，还是营造情绪。只有前者必须依赖对应真实产品/事件的材料；图库与生成画面可表达氛围和概念，但不能作为产品实测证据。导演的 claims 仍在 storyboard.json，不在素材清单里再维护一套核实状态。

| 类别 | 选用时核对 | 常见替代 |
|---|---|---|
| 界面与操作 | 产品版本、测试数据、关键状态/结果可见，隐私和真实用途清楚 | 自有测试环境重采；无法操作时用明确标注的示意图 |
| 图片与录像 | 主体准确、能留字幕空间、裁切后清晰，无不适用的水印或画面元素 | 换构图/镜头，真实截图配标注，或生成概念素材 |
| 音乐与音效 | 实际审听可用段、干净结尾、循环接缝、情绪与人声兼容性 | 已有可用音乐、降低配乐密度或保持安静，不强行填满 |
| 字体、Lottie、模型 | 字形/外部图片/贴图等依赖齐全，格式能被当前工程消费 | 本地字体、SVG/基础几何体；复杂素材先做代表帧 |

技术检查按实际文件使用已有 ffprobe、图片预览和对应组件；短预览通过不等于完整文件没有问题。素材选择只确认候选是否适合接入，最终合成后的可读性、节奏和声音仍需检查。

## 最小记录，复用已有文件

少量素材直接补在 brief.md 的素材段落；已有来源表则更新原表。记录数量增多时可维护项目内一份 Markdown/JSON sources 文件并从 brief 链接，不强制迁移。以下是可裁剪的记录示例，示例值不是已经核查的真实素材：

```markdown
### 素材：demo-export
- 使用文件：capture/recordings/export.mp4
- 对应镜头：storyboard 中的 export-result
- 来源：自有产品测试环境，实际产品版本/构建号
- 取得：录制日期、录制方式；使用演示数据
- 使用条件依据：自有录制；另核对画面中第三方图片/音乐
- 技术范围：实际分辨率/时长；已看关键操作与结果，其他范围待审
- 选择理由：完整展示同一次操作的导出结果
```

外部素材另记录原始来源页、作者、条款页/许可文件、核对日期、与本次用途相关的限制和署名文本。来源页与下载直链不同，优先保留能定位作者和条款的来源页。需要时保留允许保存的许可说明或订单/授权依据，去除账号与付款敏感信息；无法确定的用途写待确认，不只填写“可商用”。

“免费”、搜索结果摘要、能下载、存在 LICENSE 文件，都不能单独证明本次使用条件已满足。按实际来源核对发布范围、修改/衍生和署名等相关要求；不把目录整体许可自动套到目录内所有第三方素材。

同名可能变化、经历裁剪/转码或来自持续更新的共享库时，记录实际输入哈希和派生关系最有帮助。可在 PowerShell 使用 `Get-FileHash -Algorithm SHA256 -LiteralPath '<实际文件绝对路径>'`，把结果附在原记录；哈希用于确认版本，不证明来源真实或许可成立。衍生文件引用原素材记录，只补裁剪/转码参数，不再复制一份来源条款。

实际接入前检查素材在项目里的文件路径、依赖与记录一致。未下载/未生成标候选；文件已取得但使用条件未确认或依赖缺失标待处理；交给制作时说明剩余项。不要为推进状态伪造通过。

## 制作与归档交接

署名有需要时交给 publish 放到实际平台允许的位置，并保留在交付说明；片内声明需要画面修改则回导演/制作处理。来源记录与素材随本项目归档，确认 archive.json 包含所需文件；大媒体及被排除的文件另按流程备份并试恢复，不以保存 URL 代替原始输入。不要把临时候选、账号页面或无关下载一起塞入共用库。
