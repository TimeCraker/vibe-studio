# 素材搜集与选材

先读项目 brief.md、storyboard.json 和已有素材，找出真正缺少的镜头输入。按用途、画幅/裁切、长度或分辨率、声音情绪、使用场景和已有预算选材；已有合适素材直接复用，不要求每次联网或搜齐所有类别。

## 搜集与选择

优先本项目实际输入 → 来源明确的共用资产 → 用户/产品官方材料 → 可核实来源的素材库。搜索时从镜头需要出发，例如“机房远景，横版，能留出字幕空间”，而不是搜“高级科技感”。连接器可完成的查询优先使用连接器；外部搜索、素材条款和当前下载方式以当次可访问来源为准，不在技能里维护平台白名单。

先比较能影响选用的差异：内容是否准确、主体与全片是否相容、可裁切空间、技术质量、使用条件和取得成本。满足镜头需要就停止扩搜；缺项回报具体替代方案，不为凑候选数收集大批无关素材。详细判断和交接格式按需读[选材与来源记录](references/selection.md)。

| 素材需求 | 交接给谁 | 应取得什么 |
|---|---|---|
| 产品操作、界面与结果 | content-director 设计演示，web-capture 或实际可用录制工具采集 | 真实使用版本的截图/录像；未采集时只交录制需求 |
| 架构、流程或数据图解 | video-motion 的技术可视化分支 | 原始事实/数据与表达要求，不用无关图库代替图解 |
| 现成图片、录像、音乐、音效、模型 | 当前可用素材来源或本地库 | 可读取原文件及必要依赖、来源与使用条件 |
| 需要生成的插画/背景 | content-director 视觉选路及环境 imagegen | 已有候选/参考与美术简报；实际生成后才登记文件 |

## 交付与边界

实际选用文件保存在项目中，Remotion 输入可直接落在项目 public/ 对应目录；记录该文件而非库里同名文件。核对本地文件能打开、媒体时长/尺寸/格式、声音和模型依赖；没有听音或加载模型的能力时标明未核查范围，不把文件存在写成效果通过。

在已有 brief.md 或素材来源记录中保留文件与镜头用途、创作者/来源页、取得日期、使用条件依据及待处理的署名。多素材可单独维护一份 sources 记录，brief 只链接它；不再复制完整清单到 README。使用条件不明确的文件保留候选状态，换用有依据的素材或回导演改表达。

使用来源提供且当前工具支持的获取方式；不绕过登录、付费或下载限制。远程媒体优先用工具原生预览，不为绕过显示限制下载。下载不可用时交候选链接和缺项，不能声称文件已入库；付费、订阅或外部上传沿用已有授权范围，没有预算就先选可用替代。

最终说明选用了什么、服务哪些镜头、还缺什么。交给制作技能做实际接线与样片，交给 media-qc 核查使用效果；项目专用素材留在项目，只有来源清楚且确有复用价值的资产才按[资产约定](../../assets/README.md)回流。归档沿用[总流程](../../workflows/explainer-video.md)，来源说明、实际输入和需要履行的署名一起保留。
