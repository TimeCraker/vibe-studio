# 专项视觉制作

先由 content-director 给出镜头意图、事实与来源、主体和本片视觉方向；按当前需求读取本页对应分支。输出写到制作项目，不往技能里放专用内容；现有 scene-kit、版式和资产优先复用。专项能力不强制成为每条片子的步骤。

## 技术可视化

visual-explainer 作为本技能内的方法使用，暂不新增技能入口。输入来自 storyboard.json 的 claims、scene 目的与真实材料；输出是项目内可编辑 SVG、图形场景代码、使用到的数据与样片。

| 要解释的关系 | 推荐表达 | 先检查什么 |
|---|---|---|
| 模块如何协作 | 按实际调用顺序揭示路径/状态，复用 DrawPath 和标注 | 不是把模块名字排成装饰性架构图，箭头方向和边界有依据 |
| 操作与结果 | 真实录像/截图配合 DeviceFrame、局部放大和对应标注 | 观众能看到关键操作及结果，界面数据不是生成的 |
| 前后差异 | 同一任务、同一口径的对照，强调变化位置 | 不能用不同条件制造夸大效果 |
| 数值与趋势 | 根据问题选条形、折线、分布或直接标注，现有 ChartGrow/CountUp 按需用 | 单位、分母、时间窗口、坐标与来源清楚；缺失项不补成零 |
| 原理或状态变化 | 分步揭示主体、关系和变化，复用 SVG/ShapeMorph | 画面确实解释因果或过程；明确示意，不能把相关性画成已证明因果 |

施工时先画稳定完成态，再按信息顺序分层，最后加解释变化的运动。图内文字和真实数字由排版/数据层绘制，不交给位图生图；不要把整张信息图扁平化后再试图分别驱动对象。Remotion 时序从 useCurrentFrame() 派生，数据固定或有明确输入版本，不使用自行计时的图表动画。

先用代表帧查主体、标签和尺度，再播放关键片段查理解顺序与阅读停留；静音可检查画面是否提供足够信息，有配音时还须检查对应关系。修改回写源 SVG/场景/数据，不直接修生成截图。

## Lottie 素材

全局 lottie 指导可用于选材和理解素材，本仓视频接入复用 LottieLayer。将 JSON、依赖图片/字体按本地可渲染形式放入项目；素材来源与许可按[资产约定](../../../assets/lottie/README.md)核对，不把平台的“免费”标签当成所有用途的保证。未经兼容验证的 expressions 不进入现有渲染链。

- 内联 animationData 优先；使用 src 时相对项目 public/，加载失败必须停止渲染，不能把空白画面当成功。
- loop 建议逐镜显式指定；本仓包装器沿用既有默认 true，单次动作设 false。delay 单位秒，从该局部时间开始；playbackRate=1 表示素材原速，包装器针对锁定引擎按“素材 fps / 合成 fps”换算底层速度。升级后以实际跨帧率渲染检查此契约，不照搬新版本默认行为。
- .lottie 压缩包不能直接传给只接受 JSON 的现有组件；先按素材工具/许可导出完整 JSON 与依赖，或在项目中验证可用播放器，再接入。网页 autoplay 不属于这里的时间轴契约。
- 渲染延迟前、开始、动作中和结束附近的代表帧；循环素材额外检查接缝。改变输出 fps 后核对同一秒的动作位置，不用经验比率修速度。

## 3D 产品与空间镜头

有结构、体积或相机运动的表达收益时复用 ThreeStage；单纯装饰可继续使用 2D。先核对模型/贴图来源、单位、朝向和真实产品比例。没有可信模型时可以明确交付概念示意，不把自动造型当实物结构。

本仓 ThreeStage 接受 width/height、cameraZ、fov、dpr、style 与 R3F children，真实相机/场景动画由项目实现；它不是自动建模器或任意文件的零配置加载器。加载模型与贴图的代码应等待资源完成，失败要明确停止；输入模型、贴图和实际配置随项目归档。

运动、相机与灯光变化由 useCurrentFrame() 派生，不使用实时 useFrame()/时钟累加。先用小尺寸和代表帧验证材质、轮廓、遮挡、相机裁切与文字，再渲染短片，按实测耗时决定规模。GPU/软件渲染差异记录到项目，不用固定镜头配额代替性能判断。ThreeStage 的背景、尺寸与景深关系要与全片视觉方向一致。

先核对本地接口与类型，官方原理参考 [ThreeCanvas](https://www.remotion.dev/docs/three-canvas)。不要因为当前线上文档提供新 API 就升级本仓锁定版本。

## Remotion 官方专项

按需查 [官方技能目录](https://www.remotion.dev/docs/ai/skills)：maps 用于地图/路线/区域变化，interactivity 用于让 Studio 元素可选择/编辑。已有综合官方参考不等于所有新专项 API、依赖和服务都已接入。

先检查 references/upstream.json 的固定来源、本地参考内容和模板包版本；只加载本任务相关指导，不运行 create/upgrade 替换工程。地图数据、底图、地理坐标与产品事实分开核对；需要外部服务时先确认实际可用连接、素材条款和预算，未接入就使用来源明确的静态 SVG/地图数据。

Studio 可编辑性在实际预览中测试：只暴露有意义的参数，修改仍回到项目源配置，重新渲染并检查结果；“可以在 Studio 打开”不等于参数已可编辑。各分支的最终文件仍由 media-qc 检查，按实际视听范围记录审稿。
