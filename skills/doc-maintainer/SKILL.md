# 文档维护

工具正本是本 skill 上两级目录中的 scripts/docs.mjs。跨仓库使用时先由 skill 的实际路径定位工具绝对路径，命令加 --repo 指向目标；不要假设其他仓库也有同名脚本。

代码修改收尾运行 `node <工具绝对路径> maintain --repo <目标仓库>`。它只改已有受管生成区，并列出候选文档、来源路径与行号。阅读本次 diff 和相关实现，在同一任务中直接修订受影响的现有说明；已经改过的文档也需核对是否准确。unmapped 表示缺少直接引用，涉及公开行为时仍需检查入口说明。

只有无法从实现和既有授权判断的业务意图才向用户确认。无语义变化时可以说明无需改文档；不为填清单创建额外状态文件、逐次总结或报告。局部修复只更新对应段落，历史验收与制作配方保持快照。工具候选不是“已过期”的定论。

生成区用 `<!-- docs:auto ... -->` 标识，只通过工具更新；当前支持根 README 的 skills、tree、commands、versions 块。新增技能后跑 sync，再检查 diff；CLI 命令声明与帮助共用 JSON。保存边界和工具命令见[维护说明](../../docs/documentation.md)。

提交钩子读取暂存区，不改写、不暂存文件。它只拦生成漂移和新增坏链接，语义提示由当前 Agent 处理；部分暂存出现不一致时检查实际 index，不用全量 git add 掩盖。CI 使用 check 做确定检查。

查找知识运行 `node <工具绝对路径> search --workspace <工作区> --query "关键词"`，需要历史资料才加 --history。搜索使用中文/英文词项，可换同义词重查；不是向量问答。读取结果指向的源文档和实现，不把 unverified 或 needs-review 当作已经核对。索引是可删缓存，无外部模型或网络调用。
