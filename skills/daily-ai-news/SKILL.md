# 每日 AI 资讯

本栏目由 Agent 判断新闻和设计内容，共用命令处理确定的制作操作。先判断有没有值得报道的内容；值得时先交可照读的口播稿，用户录音后以实际音轨决定节奏。正式语音、素材取得、成片、审阅与投稿分别记录真实状态；不能为了测试凑新闻，也不承诺外部平台或任意模型永不失败。

## 新会话从这里接手

不依赖聊天记录或上个 Agent 的记忆。先运行 `node skills/daily-ai-news/scripts/edition.mjs status` 查工程，再对本次指定的一期执行 `status --project <目录>`。读取命令列出的本期文件和[生产运行手册](references/production.md)，按 `stage` / `next` 继续。用户给的是上一期录音时续做那一期，不能擅自改成今天；用户要新一期时用 `init --date YYYY-MM-DD [--source URL]` 建空工程，不能整目录复制旧新闻。

新工程用共用初始化、录音保全、词级转写/对齐、代码版式、渲染和投稿物料入口。现有工程保留自己的 `job.json` 和已交付文稿，按该工程已声明步骤续跑，不强制迁移、重建或从头重跑。`status` 是文件证据和接手提示，不代替核实；`check --phase script|render|delivery` 检查相应输入/版本。命令和数据字段以运行手册及解析器为准，失败先读具体错误，不能仅修改状态字符串绕过。

接手的 Agent 需要能读写本地文件并运行 Node/Python/FFmpeg；找资讯需要可用网络或浏览器，渲染需要锁定 Remotion 依赖和 Chrome。缺能力时先完成不依赖该能力的工作，明确缺项和续跑命令，不伪造成片、检索或发布成功。

## 开始前

读取仓库 AGENTS、[栏目 Stage Spec](../../docs/2026-10-23-daily-ai-news-spec.md)与[制作流程](../../workflows/explainer-video.md)，检查 Git 状态。按需读取相关内容技能，不复制其规则。保留他人改动；已有本期工程先检查并续跑，不重建或覆盖。

确定本期日期、来源与交付范围。未指定日期时使用客户端 Asia/Shanghai 的当天日期；明确给出日期则制作该期，不因执行已跨零点就改题。[Cursor 首期任务](../../docs/2026-10-23-daily-ai-news-cursor-prompt.md)仅作历史，不把其中日期、新闻、排行榜或测试配音当日常默认。

视觉仍为纸白＋珊瑚色的瑞士报刊风，直接按[视觉约定与本地参考](references/visual-style.md)实现；榜单优先用户最新截图的“左侧前三名、右侧第 4 至 15 名”构图，原有本地图片保留为辅助参考。不重新要求选风格，不调用生图。首次代码样片先用 16:9、1920×1080；首期与后续日更均采用原生 60fps，时长随有效新闻调整。4:3 必须重排，不能拉伸或把多张画面拼成长图。

## 每日工作顺序

先做选题和是否出片的判断，再进入制作；新闻条数、板块数量和视频分钟数都没有固定配额。重点是可靠、有独立价值、主次清晰。

1. **取材与筛选。** 先独立检索当天及近期有实质变化的 AI 新闻，覆盖模型发布、产品/工具更新、开源与重要研究，优先查看官方公告、更新日志和原始仓库，形成第一轮候选；不只围绕参考文档里的名称搜索。再读取用户给出的当期文档，作为补充线索，与独立候选合并、去重、回溯原始来源并比较价值。没有文档也可启动；检索记录简要区分主动发现与文档补充，检索受阻时说明覆盖缺口，不声称已全面搜完。content-director 核对事件日期和来源，按重要变化、实际用途和时效选题，合并重复事件。有价值的新闻多，就按头条、次重点和简讯分层，必要时按专题组织；不因条数上限机械删减，也不平均分配篇幅。有价值的新闻少，可以做短刊；只有一条但足以支撑独立内容时，可做单主题片。合理检索与核实后没有合适内容，就记录“今日不出片”并结束本次制作，不为播放榜单或维持日更而凑片。官方宣称、第三方评测与推测分开表述；候选和主要淘汰原因保留在本期输入，正式 claims 沿用 storyboard 正本。
2. **取得开场两套 TOP15。** 从[指定 B 站入口](https://www.bilibili.com/toy/ai-model-world)发现当次页面，分别读取全球与国内筛选下的综合智力/ECI 前 15 条及时间/口径，保存原始证据与结构化快照。两页采用平齐版式，每行在模型名前放对应官方模型/产品/厂商标志。不能写死含版本号的内嵌路径。页面与[开源数据](https://github.com/liyupi/ai-model-world)可能更新不同步；切换来源在来源记录与简介中说明。画面标注按[视觉约定](references/visual-style.md)执行。保留模型 id、不同版本、原榜顺序/并列规则；缺分不补分，ECI 不写成百分数。没有同口径前次快照就不画升降。
3. **先交可朗读稿。** narration 起稿、humanizer 润色，说明发生了什么、对谁有用、具体变化和使用入口。节目顺序为全球榜、国产榜、今日资讯总览、头条与其余精选。榜单只放 BGM、不要求逐名口播；用户从总览问候语开始朗读。直接向用户贴出不带强制时间码的完整口播稿，同时保存本期 narration.md；分段和生僻词读法放在朗读正文之外，不仅交文件链接，也不让用户照已有视频的字幕速度念。镜头意图可先写，精确时长留给录音。封面围绕最有价值且可靠的模型新闻，短标题在正文兑现，使用真实官方标志；无独立模型标志则用官方厂商品牌配准确模型名。
4. **准备实际输入。** asset-scout 同时查找相关官方配图、截图及发布/演示视频；找到能直接展示所讲功能、变化或结果的可用片段时，按口播剪入，不只做静态文字页。视频与图片按内容选用，不强求每条都有视频，不以无关片段填时长。单一官网或视频平台取得失败时，继续查发布方的其他官方渠道及原帖附件，不能直接判定没有视频；按相关性和取得成本停止扩搜。素材记录分别标明“已找到入口／已取得可读文件／已剪入成片”，交付时明确实际入片的视频段落及仍用图片替代的缺项。宣传片与功能演示分开标注，不能把品牌片当作操作实测。记录实际文件、原始出处、使用条件及采用片段的起止时间；官方演示不写成自己的实测，原声按需保留并与口播协调。缺素材用来源明确的文字/图解。把实际使用版本带入本期工程，不在渲染时实时抓网页/图片/榜单。
5. **等待真人录音，再定字幕与节奏。** 默认在交稿后结束本次制作阶段，状态为“口播稿已交付／等待用户录音”，这是正常交接。等待时可准备图片、榜单、BGM和静态版式，不默认反复导出整片，也不生成 TTS 替用户录音。用户可整段或分段自然录干声，不必另加音乐或追秒。收到音频后保留原文件，转写并核对专有名词、数字和实际增删的句子，再按真实语音及停顿安排字幕、镜头、数据揭示和图片切换。音轨与稿件有事实性差异时先核清受影响句子，不把录错的数字直接固化为事实。audio-post 处理音轨和轻快、轻松的每日资讯 BGM，榜单开场可以突出音乐，口播处按实际人声避让。未做 ASR／词级校准就标明实际对齐精度；估读时长只用于预算。
6. **代码制作并实际渲染。** 默认 B 线 Remotion，复用锁定模板和字幕/动效组件，在本期工程写必要的榜单、新闻和封面场景。将本期实际 Composition、参数生成、秒与帧换算及动效统一到 60fps，以真人音轨重新定镜头时长，不把旧视觉样片秒数当目标，也不擅自加速人声；不能仅在末尾转码复制帧。先渲染代表帧/短片修正阅读和同步，再出完整样片并核对真实帧率。C 线只用于合适的已有本地 HTML/SVG。job 声明真实输入输出，失败修复后续跑受影响步骤，不升级已有依赖来回避问题。
7. **检查并交付。** 核对事实、TOP15、官标、标题截断、字体、字幕安全区和音画；media-qc 检查实际媒体，视听观察只记录已检查范围。发布物料交 publish，依授权准备或上传填表；首期测试范围见专用任务。人工终审、登录和点击发布不代填已完成。
8. **保全和迭代。** 用现有 deliverables/recipe/archive 流程保全实际输入和交付物，验证归档与空目录恢复，大媒体另行备份后才清场。将真实问题回写现有项目 README、Stage Spec 或本技能；不要在没有真实执行证据时写“每日一键流程已验证”。

## 播报稿与总览的分工

本栏目按用户的新闻播报口吻起稿。开场以“各位观众们，大家好，欢迎收看今日AI资讯”问候，随后简述当期头条及其他相关资讯；总览页列出各条具体名称和短标题，不在开场逐项念英文项目清单，也不用“改进工作方法的研究工具”“本地语音控制台”等抽象泛称吊着观众。正文每条先交代谁发布或开源了什么，再说具体变化、用途和必要限定；开源社区项目不编造公司归属，近期观察不冒充当日发布。

口播应当是连续、可听懂的播报，不是选题说明或镜头指令。完整英文名称、比较表和来源署名由画面承担，正文只读理解新闻所需的信息；必要的发布方口径、实测边界等限定仍保留。播报稿的分段说明、发音提示和画面引用放在朗读正文之外。

用户已确认的通用偏好：画面标题平实直接，口播自然口语化，都以普通观众能理解为准。总览每条先说清“谁＋发生了什么变化”，按需补一句具体用途；不只列陌生英文名和“工具观察”等分类。正文标题写完整主体和具体结论，避免“现在能用，权重还要等”这类省略对象和安排的半句话。技术名词按需配白话解释，不能为通俗而改变事实，例如模型权重开放不直接等同于开源。总览和标题随当期内容写，不固化本期新闻或口号。

用户希望参与关键文案选择：固定榜单说明、头条或总览主句拿不准时，用同一条新闻写出2至3个具体候选供对照，并简述推荐理由，等选择后再定稿；不只给抽象风格标签，不为每句普通正文增加确认。将用户已确认的偏好归纳回本节或视觉约定，未选择的措辞保留待定，不写成已认可。

## 录音交接

2026-10-24 用户确认的默认顺序是“先文稿、真人录音、再按音轨剪辑”。录音前的交付只需稿件、已核实选题与必要素材状态；用户明确另要视觉试片时才先做代表帧或 BGM 样片，标为预览，不当正式节奏。录音跨日仍保留本期日期、新闻和榜单快照；若时效发生变化，说明并核查相关句子，不静默换稿。

续跑先读本期已交付的 narration.md，核对它与旧 script/timeline 的版本关系。生成器不得覆盖已交付的录音稿；历史样片在独立恢复目录复现。收到录音并确定采用文本后，再更新制作输入、字幕与时间线，不把旧预览的校验结论沿用到新媒体。

只有用户明确改选 TTS／临时配音样片时才按 narration 与对应制作模板处理，不把测试声音当成正式配音。日常真人模式不回到首期 SAPI 测试流程；通用渲染器已把临时目录放在仓库 `.cache`。录音解码、ASR 校订、锚点和字幕验证方法见[运行手册](references/production.md#录音到制作输入)。

## 出片判断、缺源与交付

首期专用[2026-10-23 榜单参考](references/pilot-ranking-2026-10-23.json)是当日开源快照，不是现场网页抓取。仅在制作该日期的首期且在线取得失败时可明确标注来源后使用；不得用在未来日更，也不得照抄参考图里的新闻或分数。

“今日不出片”是正常完成结果：在已有本期选题记录或 README 中简要留下查阅来源、主要候选/淘汰原因和结论即可；不用为此制作空视频、配音、封面、字幕、投稿物料或媒体归档。

检索失败、来源不可读、核实不足与“已充分筛选但没有值得报道的资讯”分开记录。前者是检索受阻/待核实，不能冒称今日无新闻；缺少当期榜单也要如实处理，不能拿样本或旧数据冒充今日事实。允许交明确标记缺项的技术待审稿，不能宣布完整新闻交付。等待用户正式录音或授权时保存可续跑状态，不重复调用收费服务。

决定出片且音轨就绪后，交付可播放视频、封面、同步字幕、来源/素材记录、可重建代码与任务、技术检查和待审说明；实际时长由内容和音轨决定，不硬凑分钟数。此时必须真实渲染，不只写计划。交稿等待录音时正常停在交接阶段，不为满足“有视频”提前导出整片；不出片分支按筛选结论完成。
