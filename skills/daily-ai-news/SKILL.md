# 每日 AI 资讯

这是栏目流程草案，不是已跑通的自动成片脚本。目标是每日先判断有没有值得报道的内容，值得时用 vibe-studio 现有工具完成有重点的真实视频；首期也遵循这个判断，不能为了测试强行凑片。正式语音、采集适配、渲染与投稿分别记录真实完成状态。

## 开始前

读取仓库 AGENTS、[栏目 Stage Spec](../../docs/2026-10-23-daily-ai-news-spec.md)与[制作流程](../../workflows/explainer-video.md)，检查 Git 状态。按需读取相关内容技能，不复制其规则。保留他人改动；已有本期工程先检查并续跑，不重建或覆盖。

确定本期日期、来源与交付范围。未指定日期时使用 Asia/Shanghai 的当天日期；明确给出日期则制作该期，不因执行已跨零点就改题。首期固定日期与默认值见[Cursor 首期任务](../../docs/2026-10-23-daily-ai-news-cursor-prompt.md)。日常不自动沿用首期新闻、排行榜或测试配音。

视觉仍为纸白＋珊瑚色的瑞士报刊风，直接按[视觉约定与本地参考](references/visual-style.md)实现；榜单优先用户最新截图的“左侧前三名、右侧第 4 至 15 名”构图，原有本地图片保留为辅助参考。不重新要求选风格，不调用生图。首次代码样片先用 16:9、1920×1080；首期与后续日更均采用原生 60fps，时长随有效新闻调整。4:3 必须重排，不能拉伸或把多张画面拼成长图。

## 每日工作顺序

先做选题和是否出片的判断，再进入制作；新闻条数、板块数量和视频分钟数都没有固定配额。重点是可靠、有独立价值、主次清晰。

1. **取材与筛选。** 优先用户给出的当期文档，再检索官方公告、文档与仓库发布。content-director 核对事件日期和来源，按重要变化、实际用途和时效选题，合并重复事件。有价值的新闻多，就按头条、次重点和简讯分层，必要时按专题组织；不因条数上限机械删减，也不平均分配篇幅。有价值的新闻少，可以做短刊；只有一条但足以支撑独立内容时，可做单主题片。合理检索与核实后没有合适内容，就记录“今日不出片”并结束本次制作，不为播放榜单或维持日更而凑片。官方宣称、第三方评测与推测分开表述；候选和主要淘汰原因保留在本期输入，正式 claims 沿用 storyboard 正本。
2. **取得开场 TOP15。** 从[指定 B 站入口](https://www.bilibili.com/toy/ai-model-world)发现当次页面，读取综合智力/ECI 原榜前 15 条及时间/口径，保存原始证据与结构化快照。不能写死含版本号的内嵌路径。页面与[开源数据](https://github.com/liyupi/ai-model-world)可能更新不同步；切换来源需标明。保留模型 id、不同版本、原榜顺序/并列规则；缺分不补分，ECI 不写成百分数。没有同口径前次快照就不画升降。
3. **稿件和镜头。** narration 起稿、humanizer 润色，说明发生了什么、对谁有用、具体变化和使用入口。先展示榜单，再讲头条与其余精选。封面围绕最有价值且可靠的模型新闻，短标题必须在正文兑现，带对应官方模型/产品/厂商标志。没有独立模型标志就用官方厂商标志配准确模型名。
4. **准备实际输入。** asset-scout 获取相关官方配图、截图与演示，记录文件、出处和使用条件；缺图用来源明确的文字/图解，不塞无关机器人图。把实际使用版本带入本期工程，不在渲染时实时抓网页/图片/榜单。
5. **配音和字幕。** 沿用已选的真人/TTS/混合模式，按真实音轨定镜头与字幕。audio-post 处理已有音轨，auto-subtitle 按需转写校准。首期测试允许使用下述本地测试声音；它不决定未来正式音色。正式稿不能把按字数摊时称为精确对齐。
6. **代码制作并实际渲染。** 默认 B 线 Remotion，复用锁定模板和字幕/动效组件，在本期工程写必要的榜单、新闻和封面场景。将本期实际 Composition、参数生成、秒与帧换算及动效统一到 60fps，保持音轨与镜头时长不变；不能仅在末尾转码复制帧。先渲染代表帧/短片修正阅读和同步，再出完整样片并核对真实帧率。C 线只用于合适的已有本地 HTML/SVG。job 声明真实输入输出，失败修复后续跑受影响步骤，不升级已有依赖来回避问题。
7. **检查并交付。** 核对事实、TOP15、官标、标题截断、字体、字幕安全区和音画；media-qc 检查实际媒体，视听观察只记录已检查范围。发布物料交 publish，依授权准备或上传填表；首期测试范围见专用任务。人工终审、登录和点击发布不代填已完成。
8. **保全和迭代。** 用现有 deliverables/recipe/archive 流程保全实际输入和交付物，验证归档与空目录恢复，大媒体另行备份后才清场。将真实问题回写现有项目 README、Stage Spec 或本技能；不要在没有真实执行证据时写“每日一键流程已验证”。

## 首期测试配音

用户要求先看完整样片且没有正式音轨时，可使用模板现有的 [make_deck_audio.ps1](../video-motion/templates/remotion-app/scripts/make_deck_audio.ps1)：本机已于 2026-10-23 检查到启用的 Microsoft Huihui Desktop（zh-CN）；其他机器仍需检查。该脚本读取 narration 分段稿，`ref` 必须为 `page N`，输出逐场景 WAV。执行方式见首期任务，不把测试音色当成正式配音接受。

已有授权的合适音轨可直接用；不要为试片创建密钥、购买服务或强迫用户先录音。测试声音不可用时先排查现有本地中文声音，真实阻塞再说明。字幕工具未就绪时，试片可按实际分段音轨做保守的句级粗对齐并明确标记待校准；不得冒充已做 ASR 或词级同步。

2026-10-23 首期的实际做法：`make_deck_audio.ps1` 仍生成每页连续音轨；另外用同一只 Huihui 把每句存成 `seg-<id>.wav`，再按这些时长的比例放进该页音轨窗口。不要退回按字数摊时。本期工程的 `build-deck-params.mjs` 把 fps 写成 60，只改这一期，不改模板。这台 Windows 上 Remotion 自带 ffmpeg 不能写用户 Temp，渲染前把 TEMP 指到仓库 `.cache`。首期成片待人工审听，日更自动化还没有跑通。

## 出片判断、缺源与交付

首期专用[2026-10-23 榜单参考](references/pilot-ranking-2026-10-23.json)是当日开源快照，不是现场网页抓取。仅在制作该日期的首期且在线取得失败时可明确标注来源后使用；不得用在未来日更，也不得照抄参考图里的新闻或分数。

“今日不出片”是正常完成结果：在已有本期选题记录或 README 中简要留下查阅来源、主要候选/淘汰原因和结论即可；不用为此制作空视频、配音、封面、字幕、投稿物料或媒体归档。

检索失败、来源不可读、核实不足与“已充分筛选但没有值得报道的资讯”分开记录。前者是检索受阻/待核实，不能冒称今日无新闻；缺少当期榜单也要如实处理，不能拿样本或旧数据冒充今日事实。允许交明确标记缺项的技术待审稿，不能宣布完整新闻交付。等待用户正式录音或授权时保存可续跑状态，不重复调用收费服务。

决定出片时，交付包含可播放视频、封面、字幕、来源/素材记录、可重建代码与任务、技术检查和待审说明，实际时长由所选内容和音轨决定，不硬凑分钟数。此分支必须真实渲染，不只写计划或渲染命令；不出片分支按前述筛选结论完成。
