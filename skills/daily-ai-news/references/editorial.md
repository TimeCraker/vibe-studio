# 选题取舍与短口播

资料是候选池。Agent 先当编辑，再当播报员；默认交付已经取舍、删冗的一版，不等用户指出才开始筛选。材料、能源、芯片、生物医药和民生变化与 AI 一样按价值判断，不靠所属板块自动入选。

## 决定哪些值得播

先过事实关：能读到支撑核心说法的来源，区分发生、宣布、测试、计划与传闻，核对事件日期和既往报道。事实未核清的内容先待核，不用热度或素材丰富抵消。随后逐条回答：

- **具体变了什么？** 是新能力、可用入口、成本/性能的实质变化、可信的新研究结果，还是只换名称、上架目录、涨星和转述旧发布？
- **观众为什么现在需要知道？** 能做什么新事、会影响什么选择、解决什么问题，或带来多大的现实影响？基础研究也可有价值，但要能解释发现本身及其边界，不强编立即可用的场景。
- **本期新增了什么理解？** 与已选事件或最近已报道内容是否重复，能否合并？这一条带来的理解是否值得占用注意力？
- **需要花多少解释成本？** 陌生名词、背景、口径和不确定性是否压过了新闻本身？素材只影响表现方案，不能把画面多的普通消息自动抬成头条。

在现有 selection.json 的入选/淘汰理由中留下判断。按下面层级决定篇幅，不新增一套评分/审批系统：

| 处理 | 判断与呈现 |
|---|---|
| 头条 | 最值得观众记住的实质变化；讲清一条主线，用必要例子/证据展开 |
| 次重点 | 有独立价值，与头条相比少讲背景和旁枝，明确新变化与影响 |
| 简讯/合并 | 只需很短说明仍有独立信息价值；与同事件相关时并入原条目 |
| 备选/不播 | 价值弱、重复、仅有热度或不适合本期；给一句具体理由，待核项说明缺什么证据 |

不要求每期凑齐这些层级，不限定条数，也不因“已有三条”机械拒绝重大新消息。补丁、小更新、收费变化或安全提醒并非一律不播：广泛暴露、正在利用、明显改变成本/使用方式时可升格；仅有例行排期或特定机构截止提醒时通常不占正文。

交稿时先用很短的清单说明“推荐入片、备选/不播及原因”，再贴已经编辑过的完整口播稿。普通取舍自行完成，不逐条等确认；只有真正影响主题方向的分歧再给具体候选。新闻多时先合并和分层，不把整份文档按目录逐项播完。

## 第一版就按口播编辑

每条先写清“谁做了什么新变化、为什么值得知道”，再补理解所需的例子、证据和限定。头条可多展开，简讯说清就收；稿件长度由信息需要决定，不给每条平均分配时间，不硬卡同一字数。

交稿前自行做一遍删句检查：

1. 总览只做简短预告，正文再解释，不在开头、分标题、结尾把同一结论重复三遍。
2. 名称、参数、架构模块、机型、账号步骤和实验数字逐项问“听掉这句，会不会影响理解或使用判断？”不会就删。保留最能说明变化的例子/数字，避免把报告目录和完整规格表念出来。
3. 必要术语只解释一次，用普通观众能跟上的短句；把“将于/预计/公司自报/研究原型”等影响事实的限定留下，少写不提供信息的铺垫和口头套话。
4. 从旁白移走的信息仍要判断是否值得出现在视频中。确有需要的全名、条件可由画面承担；次要统计移到来源/简介，不把省下的字全塞回画面。
5. 同一条需要连续列很多模块、条件和对照数字时，先选一条观看主线，剩余内容压成简讯、拆为后续专题或删除；不要用“信息很全”替代清楚。

在现有 brief 或 script.meta 说明主次与大致口播预算，程序估时仅验证预算。超长先删冗、合并或重新分层，不为让校验通过抬高预算；估时通过后仍检查是否有必要讲这么久。实际收到录音后尊重已录稿，只修实际授权的问题，不静默删改已经录好的观点或事实。

## 交稿前的编辑结论

Agent 应能用一句话概括头条的新变化，并指出其余每条各自增加了什么。若某条只剩“也值得关注”，或删除后观众几乎没有损失，优先降为备选。没有值得报道的内容可以不出片；来源受阻则记录待核，不能伪称已筛完。

这份检查要求做取舍和解释依据，不把经验建议变成固定分数线、每期条数、秒数或必须覆盖的栏目配额。
