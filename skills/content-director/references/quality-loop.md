# 参考分析、事实核查与制作中审稿

## 参考片如何变成本片的方法

先明确本片受众、核心观点、观看场景与目标行为，再挑相关参考。实际观看可访问的参考片及关键片段；只有封面或截图时，只分析可见的构图和文字，不推断节奏、运镜、声音。

把观察补到已有 brief.md：参考链接/时间码、有效的叙事或视觉方法、适用本片的原因、本片怎样实现。提炼解释方式和镜头关系，不把“高级、电影感”等词当作可执行要求，也不要求模仿参考片全部细节。

在代表画面中确定字体层级、配色、真实截图的处理、图形语言与运动方式；已有品牌体系优先复用。确认可读和有表现力后再批量生产。参考图、截图和源素材按实际使用版本保存在项目，不另建知识副本。

## 事实核查的边界

对外表述先找到原始材料/官方来源，阅读能支撑该说法的具体内容；记录定位、日期和适用版本。数字保留单位、分母、样本与时间窗口，注意比较口径。实现事实优先实际代码/运行结果，当前外部事实核对当时来源。

材料互相矛盾时比较版本和范围；仍无法确认就保留 needs-check、删减承诺或明确不确定。不能只因有 URL/checkedAt 就标 verified，日期与字段校验不证明内容真实。claims 沿用 storyboard.json，原始文件和来源定位可追溯；未核实的声明不进入最终事实性字幕。

## 从分镜到粗剪

逐镜判断：它在解释什么、观众应注意哪里、是否增加信息、为何需要运动，以及与前后镜头如何连接。界面操作和结果用真实录制；关系、比较与步骤用图形；情绪和想象场景可用生成素材，不能替代事实证明。

在[动态分镜](animatic.md)中先完整看一遍信息结构与临时音轨，再查关键片段：结果有没有展示就提前切走、旁白是否领先画面、字幕是否抢主体、是否留够理解时间。已有成熟系列、短小改稿可简化，不强制固定镜头数、时长、样片轮数或持续运动。

问题写成“对象版本 + 时间码 + 可观察现象 + 修改位置/建议”，交回分镜、口播、源网页或场景代码。修复后重渲染受影响内容；调整顺序、音轨或总时长时再看完整衔接。最终版本使用 media-qc 的视听审稿记录，技术结果与人工接受分开。

## 按片型扩展

设计、生图、技术可视化、Lottie、3D 和 Remotion 专项的调用与交付边界统一见[视觉能力选路](visual-routing.md)。不在此另维护一份工具安装或接口说明。

确需生成式镜头时：先选参考画面与主体风格，再围绕具体动作生成短素材，逐镜筛选一致性和瑕疵，接回原剪辑。使用前确认实际工具、授权范围和费用预算；失败只做有界、可知成本的重试。没有工具则保留简报与缺项，不新增空壳 ai-shot 技能或把关键产品操作改成生成画面。
