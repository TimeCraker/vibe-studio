# projects/ — 施工流水线（临时作业空间 / Ephemeral Workspace）

> **核心哲学**：制作配方可恢复，计算缓存可清理。
> `projects/` 是动态作业空间。交付后先把源码、时间轴、字幕、发布配置和素材清单归档至 `products/`，逐文件校验哈希并验证恢复；未通过校验时保留现场，不删除唯一一份输入。

---

## 开工与交接

- 初始化命令与技能入口见[项目首页](../README.md#开始使用)；视频制作顺序、A/B/C 选择与可裁剪阶段见[制作流程](../workflows/explainer-video.md)。本文件不另维护一套生命周期。
- 在研项目的 README 记录当前阶段、下一步、阻塞项和证据入口；已有说明可直接补充，格式与状态归属见[维护约定](../docs/documentation.md#作品状态记录)。
- 文案、场景代码、时间轴、项目专用原始素材与日志在各项目内管理；不把专用素材或临时修补直接写入共用模板。
- `studio status` 返回步骤执行状态；分镜/成片人工接受与真实发布按维护约定记录，脚本只负责投稿填表。

## 保存边界

归档、校验、试恢复和大媒体备份的具体步骤统一见[制作流程](../workflows/explainer-video.md#7-归档清场与后续复盘)。完成后可清理缓存或施工区，也可保留有用现场；不要求为了目录整洁删除工程。

归档后以作品根 README 为当前入口，后续运营数据可写入 operations；固定配方和交付快照不原地修改。Git 克隆不等于恢复了大媒体。

本目录说明不维护“所有工程已完成”等动态结论。当前工程以实际子目录与各项目说明为准；历史作品的交付证据、输入缺失与恢复范围查看[作品目录](../products/README.md)及各自记录。
