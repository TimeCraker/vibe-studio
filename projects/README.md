# projects/ — 施工流水线（临时作业空间 / Ephemeral Workspace）

> **核心哲学**：**施工区即中间态，交付即清场**。
> `projects/` 是应用技能（Skills）进行内容生产的动态作业工坊。它不是长期存放工程源码的陈列室，而是真正干活的脚手架现场。**任务一旦交付至 `products/`，本目录对应的施工现场即刻清场销毁**。

---

## 施工生命周期（四阶段闭环）

```
┌──────────────┐     ┌──────────────┐     ┌──────────────┐     ┌──────────────┐
│  1. 立项开工  │ ──> │  2. 编排施工  │ ──> │  3. 验收交付  │ ──> │  4. 回流清场  │
│ projects/<id>│     │  调用 skills │     │ 沉淀 products│     │ 彻底删除施工区│
└──────────────┘     └──────────────┘     └──────────────┘     └──────────────┘
```

### 1. 立项开工（Setup）
- 依据任务类型（PPT / 讲解成片 / 介绍成片）在 `projects/` 下新建作业目录：`projects/<项目名>/`。
- 复制对应技能模板起步：
  - **介绍成片 (B 线)**：复制 `skills/video-motion/templates/remotion-app/` 到 `projects/<项目名>/remotion-app/`。
  - **代码采集成片 (C 线)**：复制 `skills/web-capture/templates/` 起步，配置 `shots.json` 与导演页。
  - **PPT 生成**：调用 `skills/ppt/` 模板脚本起步。

### 2. 编排施工（Build & Animate）
- 在该隔离沙盒内进行文案打磨（`narration` + `humanizer`）、动效组合（`scene-kit` / `patterns.md`）、时钟校准与录制渲染。
- 施工期间产生的临时帧（`frames/`）、过程素材、临时日志均局限在该项目目录内，严禁污染外围。

### 3. 验收交付（Deliver to products/）
- 渲染完成并通过多级视觉核查、终审。
- 启动 `skills/publish` 完成跨平台表单填写与最终发布。
- **成果归档**：将不可变的交付产物沉淀至 `products/<项目名>/`：
  - 最终封面图片（PNG）
  - 最终发稿文案元数据与话题配置（`PUBLISH.md` / `form.json`）
  - 最终成片信息、字幕文件（SRT）及验收报告（`README.md`）
  - （若是代码画 PPT，可将最终可复跑的生成脚本归档于产品目录内）

### 4. 回流清场（Teardown & Cleanup）
- **通用能力回流**：若施工过程中提炼出了新组件、新动效、新成页范式，将其沉淀至 `skills/video-motion/` 或 `assets/patterns.md`。
- **施工现场清场**：
  - 彻底删除 `projects/<项目名>/` 目录及其所有中间过程帧与依赖。
  - 保持本目录（`projects/`）极简、轻量、随时待命。
