# ppt skill 文案与叙事规则重构

2026-08-28 · 由 vibe-studio 介绍 deck 的实际产出触发，经无上下文 agent 诊断验证

## 起因

用 ppt skill 给本仓库做了一份对外介绍 deck，通过全部三级核查（初筛 0 问题、盲看 0 问题），但用户判断「文案没讲明白，默认观众已了解项目」。派无上下文子代理以零基础观众视角复检，结论一致，并定位到规则层缺陷（非执行走样）。

## 诊断出的缺陷（按严重程度）

1. **无受众规则**：取材只问「真不真、挖得深不深」，不问「观众需不需要」。素材源是仓库内部文档，产出必然带内部梗（EntryEffect 3954、blader 体系、forest 主题预设）
2. **无叙事结构规则**：挖完素材直接跳逐页文案，无大纲环节；概念前向引用（三级核查第 3 页使用第 6 页才解释）；实际产出 10 页 9 种范式各一次，成了范式能力巡展
3. **密度标准前置到初稿**：四条标准 + humanizer 风格约束初稿的产出过程，初稿即终稿，结构级缺陷（无受众、无叙事线）无环节可暴露
4. 黑话禁令错位：禁商业八股，不禁技术行话；句子去味成功、页面理解失败
5. 验证闭环只查像素不查理解：盲看四项纯视觉，观众「看不看得懂」无质量门

## 改了什么（SKILL.md）

- Step 1 开头加**受众三问**（给谁看 / 观众已知什么 / 看完复述什么），所有取舍用它裁决；素材加「观众不需要的事实不进正文」
- 加**大纲先于逐页**：一条主线 + 开篇三答 + 每页在论证链的角色；禁前向引用；连续两页不承接 = 重排
- 加**两遍成稿**：第一遍写足（零基础叙述体，允许长），第二遍才 humanizer 去味 + 四条标准修剪。明确「humanizer 是打磨器不是初稿模板」
- 黑话禁令分两层：商业八股直接删；技术行话按受众过滤
- 范式表头升级为程序性规则：按叙事大纲选范式，同范式可重复，禁集邮式范式巡展
- Step 4 盲看加**观众复述测试**：子代理只看前 1/3 页回答「是什么 / 给谁 / 解决什么」，答不出打回文案

## 放弃了什么、为什么

- **不改「四条密度标准」本身**：它们管的是句级质量，缺陷不在标准内容而在施加阶段（初稿 vs 打磨），挪到第二遍即可
- **不给范式表加「推荐页面序列」**：那会把「硬套」从 9 范式换成另一套固定模板，与「叙事先行」矛盾；正确约束是程序性的（大纲先定、禁集邮），不是给出新模板
- **不回改已交付的 vibe-studio deck**：产物可再生，等下次用新规则重做时一并体现；顺手发现口径漂移（deck 写 17 范式 / SKILL.md 表 15 行 / 实数 19 个范式函数），留待下次生成时对齐

## 验证方式

下次任一 deck 生成时：文案稿应先出现受众三问 + 叙事大纲再出现逐页内容；盲看阶段跑观众复述测试。
